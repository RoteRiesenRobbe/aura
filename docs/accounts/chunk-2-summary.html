Aura — Accounts & Persistence

Step 8a, Chunk 2: the front door

Point-in-time summary · 1 August 2026 · branch accounts-8a · commit de8d6910

This is a human-facing snapshot, not a maintained document. The authoritative sources are docs/archive/plan-accounts-frontend.md §4–§7 (the screens and the flows), §10b (the ten execution rulings) and §10a (the full chunk ledger). Where this document and those disagree, they win.

In one sentence

Chunk 1c built accounts you could only reach with a command-line tool; this chunk gives them screens, so a brand-new player now types a name, presses one button, and is in the world — with an account quietly created behind them that they never had to think about.

You can now click through the whole thing: create a character, play, come back later to find it waiting, sign up for a real account without losing anything, log out, log back in, and delete a character.

What a player actually sees

Moment What happens
First ever visit A create-your-character screen: a portrait, a name field with a suggestion already in it, and a Create button. Underneath, a quieter “Already have an account? Log in”.
Pressing Create Straight into the world. No second click, no “now choose your character” step for a player who only has one. An account is created behind the scenes and remembered in the browser.
Coming back later A character-select screen: three cards side by side, one per slot, each showing the character’s portrait, name and level, with Play and Delete. Empty slots offer to create someone new.
While playing, without an account A small banner near the bottom: “Your progress lives only on this device.” It can be dismissed, and it never comes back in that session.
Signing up From the settings panel. It takes a username and password, and says plainly that password recovery does not exist yet. Signing up keeps everything — it adds a login to the account you were already playing on, and drops you straight back into the world.
Deleting a character A confirmation box whose Delete button is greyed out for five seconds, counting down.

Decisions worth knowing about

You can only log in when you are logged out

There is no “Log in” anywhere inside the game — only on the opening screen. That looks like a missing feature and is deliberate.

Logging in switches to a different account, and switching away from an unregistered account throws that account away. If you could do that mid-game, the character you were playing at that moment would be among the things thrown away. Rather than write a guard against it, the door is simply not there.

The cost is that leaving the world needed its own way out, so the settings panel gained “Leave to character select”.

The delete countdown is not a security feature

The five-second delay exists so nobody deletes a character by misclicking. It protects against an accident, not against an attacker — anyone determined can bypass it entirely. It should never later be mistaken for a limit on how often characters can be deleted.

Names are permanent now, which changed two small things

Character names became globally unique, so the game no longer pre-fills the last name you used — that would guarantee a rejection. It still suggests one. And because the suggester draws from a fairly small pool, if it proposes a name that is already taken it now quietly tries another, rather than blaming the player for a name the game itself offered.

How it was checked

  • A new automated browser test that plays through the whole thing — cold visit, create, auto-enter the world, sign up, come back, log out, log in, open the delete box: 21 of 21 checks passed.
  • The existing 19 browser tests were all updated to enter the world the new way and re-run; the ones covering conversations, three-player XP sharing and the network format all pass.
  • Server test suite 32 of 32, browser-code tests 87 of 87 (up from 76), and a clean server start with no errors and no warnings.
  • An open question from the previous chunk was settled. Chunk 1c had to assume that browsers would accept the security-flagged login cookie over an unencrypted local connection, because it had no browser to try it with. A real browser was used this time: they do, in all the configurations the development setup uses. No change to how the game is run was needed.

What is deliberately not here

  • Your progress still does not survive a restart. The account and the character persist; their level, skills and quests do not yet. That is chunk 4, and it is worth saying plainly because until then a returning character looks correct and is back at level 1.
  • No avatar picker. The portrait is shown but cannot be changed, and there is deliberately no greyed-out button hinting at one — a disabled control reads as broken.
  • No password recovery. The sign-up screen says so directly. Until that ships, a forgotten password cannot be recovered.
  • No graveyard or history view for deleted characters.

Two things to watch

A mistake was caught twice, in the same shape. Test accounts use a reserved name prefix so they can never collide with a real player. The obvious way to let the test tools claim that prefix was to allow it for accounts that have not signed up — which sounds narrow, but every new player is in exactly that state at the moment they create a character. It would have handed the reserved names to everybody. It is now restricted to development mode instead, so the live server refuses them outright: stricter than before, not looser.

The test tools now leave traces. Before this chunk, everything a test did vanished when the server restarted. Now each run creates a real account row. A cleanup command was built alongside, and it refuses to run against anything other than a local database — the tests must never be pointed at the live server.
